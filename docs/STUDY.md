# 스터디 — 사람 기보 학습 · 패치/새 기믹 적응

이 문서는 두 가지 질문에 대한 조사와, 그 결과로 이 프로그램에 넣은 것을 정리합니다.

1. 쇼다운 기보(리플레이)로 먼저 배우려면 어떻게 하나
2. 패치가 나오거나 새 기믹이 생기면, 처음부터 다시 학습하지 않고 어떻게 따라가나

## 1. 다른 프로그램·연구에서 배운 것

| 사례 | 한 일 | 우리에게 주는 점 |
|---|---|---|
| **AlphaGo** (DeepMind, 2016) | 사람 기보로 정책망을 먼저 지도학습 → 자기대전 강화학습으로 미세조정 | "기보 먼저, 자기대전은 그다음" 순서. 처음부터 자기대전만 하는 것보다 출발이 빠름 |
| **AlphaStar** (DeepMind, 2019) | 사람 리플레이로 지도학습 → 리그(여러 상대) 강화학습 | 리그 상대 다양화 — 우리 밤샘 학습의 리그(수읽기·과거 신경망·기본 AI)와 같은 구조 |
| **OpenAI Five** (OpenAI, 2019, arXiv 1912.06680) | 10개월 학습하는 동안 Dota 2 패치·관측 변수·신경망 크기가 계속 바뀜 → 매번 처음부터 하지 않고 **"수술(surgery)"** 로 이어서 학습. 새 입력은 기존 출력을 바꾸지 않게(가중치 0) 붙이고 이어서 학습 | 패치·새 변수 대응의 핵심 방법. 이 프로그램에 그대로 구현함 (아래 3장) |
| **Net2Net** (Chen·Goodfellow·Shlens, 2015) | 학습된 신경망을 '출력이 그대로인 채로' 넓히거나 깊게 만드는 방법 | 수술의 이론적 바탕 (함수 보존 변환) |
| **Metamon** (Grigsby 외, 2025) | 쇼다운 관전자 리플레이에서 **각 플레이어 1인칭 시점을 다시 만들어** 대규모 오프라인 학습 | 우리 리플레이 해석기와 같은 생각. 숨은 정보(상대 세트)는 학습에 쓰지 않고, 자기 세트는 판 전체에서 드러난 것 + 추정으로 채움 |
| **Foul Play** / **PokéChamp** / **VGC-Bench** | 탐색(기대값 미니맥스·MCTS) 기반 봇, LLM+미니맥스, 더블 배틀 벤치마크(지도학습+리그) | 지금 가장 강한 것은 '탐색'. 신경망은 탐색의 길잡이(사전확률·판세 평가)로 쓰는 것이 효율적 — 우리 수읽기 AI 구조 |
| **연속 학습(continual learning)** 연구 — 망각(catastrophic forgetting), EWC(Kirkpatrick 외 2017), 경험 재생(Rolnick 외 2019) | 새 데이터만으로 학습하면 옛 지식을 잊음. 옛 데이터를 조금씩 섞는 **리허설(경험 재생)** 이 단순하면서도 강한 방법으로 자주 보고됨 | 패치 후 미세조정 때 옛 기록·사람 기보를 섞어 학습 (리허설) |

## 2. 쇼다운 기보 학습 — 구현과 검증

### 흐름

```
replay.pokemonshowdown.com  →  tools/fetch_replays.py fetch   (원본 로그 보관: userdata/replays/raw/)
                             →  tools/fetch_replays.py parse   (engine/replay_parse.py: 양쪽 플레이어 시점 재구성)
                             →  tools/fetch_replays.py train   (기보만으로 모방학습 → 기본 AI 들과 평가 → 더 나으면 채택)
밤샘 학습은 회차마다 새 리플레이를 받아 학습 데이터의 30%(--replay-share)를 사람 기보로 섞는다.
```

### 리플레이 해석이 어려운 이유와 처리

- 리플레이에는 **요청(그 순간 고를 수 있던 선택지)** 이 없다 → 그 플레이어의 요청을 다시 만든다.
  - 자기 세트: 판 전체에서 드러난 기술·도구·특성(그 플레이어는 원래 아는 정보) + 안 드러난 칸은 메타 통계로 추정. `|showteam|`(공개 팀 시트)가 있으면 그것이 정답.
  - HP: 관전자 로그는 %만 보이므로 추정 능력치로 환산.
  - 구애 고정·도발·앵콜로 막힌 기술, 2턴 기술의 다음 턴(선택지 하나) 처리.
- **실제로 한 행동**은 다음 줄들에서 찾는다: 처음 쓴 기술(대상·메가 포함) 또는 교체. 못 움직였거나(마비·풀죽음) 먼저 쓰러져 행동이 안 보이면 '모름'.
- 선출: 선봉 + 나온 포켓몬과 맞는 모든 선출을 고르게 정답으로 (안 나온 포켓몬은 모르므로).
- 더블: 대상이 쓰러져 쇼다운이 대상을 바꾼 경우는 대상을 정답에서 뺀다. `|cant|…|Disable|기술` 처럼 고른 기술이 같이 나오는 줄도 쓴다.
- 별명·채팅·관전자 줄은 정리한다.

### 검증 — 정답을 아는 우리 시뮬레이터 대전으로 (셀프테스트 `replay`)

우리 시뮬레이터 대전의 **관전자 로그만** 해석기에 넣고, 실제 기록(정답)과 비교했습니다.

| | 결정 복원율 | 정답이 후보에 들어간 비율 | 정답이 하나로 정해진 비율 |
|---|---|---|---|
| 싱글 (10판) | 92% | **100%** | 99% |
| 더블 (10판) | 91% | **96%** | 53% (대상 불확실 등) |

더블의 4%는 끝까지 한 번도 안 쓴 기술을 실제로 고른 경우(추정으로 채운 칸이 달랐음)로, 리플레이만으로는 알 수 없는 부분입니다.

**기보로만 배워도 쓸 만한가** — 같은 300판을 두 가지로 학습해 정답 기록에서 비교 (싱글, 선생님 AI 대전):

| 학습 데이터 | 행동 일치 | 승패 예측 |
|---|---|---|
| 정답 기록 (숨은 정보까지 전부 + 선생님 확률 분포) | 80.2% | 70.9% |
| **관전자 로그만 해석한 기보** (실제 리플레이와 같은 조건) | **72.3%** | **69.7%** |

→ 리플레이에서 얻을 수 있는 정보만으로도 정답 기록의 약 90% 수준까지 배웁니다. 실제 쇼다운 리플레이는 수만 판 단위로 받을 수 있으므로 양으로 보충됩니다.

> 이 작업 환경에서는 쇼다운 리플레이 서버 접속이 막혀 있어 실제 리플레이로는 아직 돌려보지 못했습니다.
> 사용자 PC 의 `밤샘학습.bat` 이 회차마다 받습니다 (`python tools/fetch_replays.py all` 로 직접도 가능).

## 3. 패치·새 기믹 적응 — 처음부터 다시 하지 않기

### 설계 원칙 (이미 들어가 있는 것)

1. **원본을 보관한다** — 자기대전은 '보이는 상태 스냅숏 + 요청 + 선택지 + 정답 분포'를, 리플레이는 원본 로그를 그대로 저장. 학습 변수는 기록 *후에* 계산하므로, 변수를 바꾸거나 해석기를 고쳐도 다시 대전하거나 다시 받을 필요가 없다.
2. **포켓몬 이름 대신 계산된 효과를 입력으로** — 신경망 입력은 "한카리아스인가?"(원-핫)가 아니라 데미지 엔진이 계산한 값(예상 데미지 %, 확정 몇 타, 스피드 비교, 상성, 위협, 남은 판세). 위력·종족값이 바뀌거나 새 포켓몬이 나와도, 데이터만 갱신되면 같은 의미의 입력이 나온다 → 처음 보는 포켓몬에도 일반화.
3. **데미지 엔진 대조 셀프테스트** — 매일 최신 쇼다운과 4,907건을 대조. 패치로 공식이 바뀌면 자동으로 실패해서 알려준다 (`update-data.yml` 은 통과할 때만 데이터 갱신).
4. **신경망은 자기 변수 목록을 같이 저장** — 불러올 때 이름으로 맞추므로 변수 묶음을 추가해도 옛 신경망이 계속 동작한다.

### 이번에 구현한 것

| 기능 | 파일 | 내용 |
|---|---|---|
| **신경망 수술** | `engine/nets.py` `surgery()` | 이름·크기가 같은 변수 묶음은 첫 층 가중치·정규화를 옮기고, 새 묶음은 가중치 0 으로 붙인다. **수술 직후 출력이 옛 신경망과 같음을 확인** (정책·가치 최대 차이 0.0000001). 이후 새 칸의 정규화만 데이터로 정하고(`fit_new_norms`) 낮은 학습률로 이어서 학습 |
| **이어서 학습** | `tools/overnight.py` `train(warm=True)` | 밤샘 학습이 매 회차 지금 최고 신경망에서 출발 (변수가 바뀌었으면 수술 후). 처음부터 하지 않는다 |
| **리허설** | `tools/overnight.py` `mixed_games()` | 학습 판 = 사람 기보(기본 30%) + 최근 자기대전. 정책 정답은 수읽기·사람·선생님 AI 의 결정만 (약한 리그 상대의 선택은 따라 하지 않음) |
| **패치 감지** | `tools/patch_diff.py` | 지난 채택 때 데이터 스냅숏 ↔ 지금 데이터: 바뀐 포켓몬·기술·도구·특성·배우는 기술·상성표 → `reports/patch_diff.md`. 관련 포켓몬에 가중치(`focus`)를 매겨 **그 포켓몬이 들어간 팀을 더 자주 대전**시킨다 |
| **게이트** | `tools/overnight.py` | 새 신경망이 지금 최고 신경망을 55% 이상 이길 때만 교체 (패치 후에도 실력이 떨어진 신경망으로 바뀌지 않게) |

### 패치 종류별 대응

| 바뀐 것 | 예 | 하는 일 | 학습 |
|---|---|---|---|
| 수치 | 위력 100→90, 종족값 조정 | 데이터 자동 갱신 → 계산 변수에 자동 반영 → 패치 감지가 관련 포켓몬 위주로 대전 생성 | 이어서 학습 (짧게) |
| 새 포켓몬·기술·도구·특성 (기존 규칙 안) | 새 메가진화 | 위와 같음 + 새 효과가 데미지 엔진에 없으면 대조 셀프테스트가 실패 → `engine/damage.py` 에 효과 추가 | 이어서 학습 |
| 규칙(레귤레이션) | 사용 가능 포켓몬 변경 | 팀 생성 풀·메타 통계가 바뀜. 통계가 쌓이기 전엔 배우는 기술 기반 추정 | 이어서 학습 |
| **새 기믹** | 테라스탈·다이맥스 같은 새 행동 | ① 시뮬레이터(쇼다운)가 새 선택지를 지원 → `legal_choices` 가 새 선택지(예: `move 1 terastallize`)를 만들도록 추가 ② 새 기믹을 설명하는 변수 묶음 추가(사용 가능 여부·남은 횟수·바뀐 타입 등) ③ **신경망 수술**: 새 칸은 0 가중치로 붙음 → 옛 기록(기믹 없음 = 새 칸 0)과 새 대전을 섞어 이어서 학습 | 수술 + 리허설 |

### 실험 — 새 변수 11묶음(199 → 319칸)을 처음부터 vs 수술로

싱글 1,401판(선생님 AI 대전 ~1,000판 + 수읽기 대전 ~400판)으로 학습, 수읽기 AI 의 결정 945개(따로 떼어 둔 60판)로 검증:

| 신경망 | 정책 손실 ↓ | 행동 일치 | 가치 손실 ↓ | 승패 예측 | 지금 신경망과 60판 |
|---|---|---|---|---|---|
| C. 지금 신경망 (옛 변수 199칸) | 1.538 | 64.6% | 0.640 | 63.3% | – |
| A. 새 변수로 처음부터 | 1.415 | 60.6% | 0.627 | 65.3% | 52% |
| B. 수술 + 이어서 학습 | **1.400** | 62.9% | **0.618** | 65.3% | 40% |

- 검증 손실은 수술(B)이 가장 좋고, 처음부터(A)보다 적은 에폭으로 도달했습니다.
- 그러나 실제 대결에서는 아직 지금 신경망을 확실히 넘지 못했습니다 (60판의 표준오차 약 ±6%p). 원인: 학습 데이터의 대부분이 선생님 AI 대전이라, 더 강한 수읽기의 판단이 적게 반영됨. → 수읽기 대전 비중을 늘리는 것이 다음 과제이며, 밤샘 학습(3060)이 바로 그 데이터를 만듭니다.
- 가치망은 한 판의 결정 수십 개가 같은 승패 정답을 공유해 1에폭 뒤부터 과적합 → 정책·가치의 최적 시점을 따로 고르도록 수정.

## 4. 앞으로

- 실제 쇼다운 리플레이로 기보 학습 (사용자 PC) → 수읽기 대전 비중을 높인 밤샘 학습으로 이어서 학습.
- 사용자와의 대전(‘AI와 대전’ 탭) 기록도 사람 기보로 쌓인다.
- 새 기믹이 실제로 나오면 위 표의 ①~③ 순서로 대응 (수술 도구는 준비됨).

## 5. 포켓몬 대전 전략 — 엔트리 · 선출 · 선봉 (추가 스터디)

> 이전까지는 게임 AI·딥러닝 쪽만 조사하고 포켓몬 전략 쪽 조사가 부족했습니다. 그래서 선출 학습이 없고 조합 시너지를 보지 못하는 설계가 나왔습니다. 이 장이 그 보완입니다.

### 5.1 공개 공략에서 배운 것

| 주제 | 내용 | 출처 |
|---|---|---|
| 선출(팀 프리뷰)의 세 가지 결정 | ① 판을 주도할 **선봉 매치업** ② 뒤에 둘 포켓몬 ③ 고른 포켓몬들로 **상대 6마리 전부에 답이 있는가** | Smogon VGC 팀 프리뷰 가이드 |
| 상대 6마리 읽는 순서 | 상대의 **메가(핵심)** 를 먼저 찾고 → **아키타입(트릭룸·날씨 등)** 을 파악 → 상대에게 **가장 쓸모없는 내 포켓몬부터 빼는** 소거법 | Pokémon Trash 전략 가이드 |
| 상대의 계획 읽기 | 스피드 조절 + 강한 공격수, 유도(따라와·분노가루) + 랭크업 같은 **짝** 을 찾는다 | vgcguide.com |
| 선봉 | 선봉이 판의 흐름을 크게 정한다. 계획을 까는 선봉, 상대 선봉을 빨리 잡는 '안티 리드' | Nugget Bridge |
| 단판(Bo1) | 첫 턴·나쁜 선봉 매치업으로 판이 끝날 수 있어 **안전한 선출**이 중요 | vgcguide.com |
| 비 파티 (챔피언스) | 패리퍼(잔비) + 브리두라스(일렉트로빔이 비에서 즉시) + 쓱쓱·물 공격수. 카운터는 **트릭룸**, 날씨를 덮어쓰는 메가 | Game8, PokéChamps |

### 5.2 우리 메타 통계로 직접 확인 (같이 쓰는 포켓몬 상관)

- **더블(VGC)**: 패리퍼–브리두라스 **+0.66** (가장 강한 짝) → 비 코어. 트릭룸 설치자(키키링·메가 가디안·그우린차·카디나르마·브리무음), 순풍(패리퍼·불카모스·엘풍·메가 찌르호크…), 속이기(포푸니크·어흥염…).
- **싱글(배틀 스타디움)**: 누리레느·타부자고·한카리아스·하마돈(모래)·브리두라스가 서로 강하게 묶인 **스탠다드 밸런스** 코어. 날씨는 하마돈·마기라스(모래), 나인테일(알로라)(설경 + 오로라베일).
- 자기대전의 메타 팀 생성기는 이 '같이 쓰는' 통계로 동료를 고르므로 이런 코어가 실제로 나옵니다.

### 5.4 이 스터디로 바꾼 것 / 바꿀 것

| 문제 (사용자 지적) | 바꾼 것 |
|---|---|
| 선출·선봉이 학습되지 않음 (선생님 규칙 그대로) | **선출망** (`engine/bringnet.py`): 내 선출(선봉 포함) × 상대 선출 승률을 대전 결과로 학습, 60×60 (더블 90×90) 전부 예측 → 균형해 |
| 1마리 차이가 다른 팀 — 포켓몬 합산 점수로는 안 됨 | 팀 대 팀 가치 = **선출 게임의 균형해 값** (조합 전체가 바뀌면 표 전체가 다시 계산됨). 이후 Siamese 어텐션 구조 검토 |
| 날씨·트릭룸·특성 시너지 | 선출망 입력에 **시너지 변수 16개**: 날씨 설치자↔수혜자(특성·타입·기술), 트릭룸 설치자↔느린 공격수, 순풍↔공격수, 벽↔랭크업, 위협 수, 선봉 속이기, 유도, 교체 기술, 짓궂은마음, 재생력↔교체, 필드, 특성으로 같은 편 약점 받아주기, 날씨 충돌, 스피드 조절 차 |
| 10팀으로 전체를 대표할 수 없음 | 신경망으로 **메타 분포에서 뽑은 수천 팀 + 저격 팀** 상대 기대 승률을 계산, 시뮬레이션은 상위 후보 확인에만 |
| 얼음·페어리 도배 같은 저격 | 팀 리그(PSRO 방식): 지금 팀 집단을 가장 잘 잡는 저격 팀을 계속 추가 |

## 6. 1단계 가능성 시험 — 요소 토큰 어텐션 인코더 (2026-10-15, 샌드박스 CPU)

**설정**: 이번 시즌 존재 924개(264종 × 세트) 쌍 85만 개의 1:1 경주 결과(−1~1)를 정답으로, 포켓몬을 종/능력치·특성·도구·기술×4 하위 토큰으로 쪼개어 어텐션으로 묶은 인코더가 맞히는가. 종 15%(39종, 존재 137개)는 **대전 데이터에서 완전히 제외**(DB 속성만 아는 종). 작은 망(d=64, 2층, 4헤드), 400스텝, numpy 만.

| 변형 | 학습한 종끼리 R² | 한쪽이 데이터 없는 종 | 양쪽 다 | 유불리 부호 일치 (학습/데이터 없음) |
|---|---|---|---|---|
| 어텐션 + 물리량 + id 임베딩(드롭아웃 0.3) — 제안안 | 0.751 | 0.606 | 0.514 | 91.2% / 85.8% |
| 어텐션 + 물리량 | 0.754 | 0.605 | 0.519 | 91.5% / 85.6% |
| 어텐션 + id 만 | 0.438 | 0.302 | 0.174 | 77.1% / 72.2% |
| 어텐션 없이 토큰 평균(bag) | 0.744 | 0.547 | 0.425 | 91.5% / 84.4% |

**결론**
1. 일반화는 **물리량(DB 속성)**에서 나온다. id 만으로는 데이터 없는 종에서 무너진다. → "새 종이 DB 에 추가되면 대전 데이터 없이도 바로 판단"이 성립.
2. **어텐션(요소 사이 관계)**은 데이터 없는 종에서 분명히 낫다 (0.55→0.61, 0.43→0.52). 학습한 종끼리는 평균 풀링과 같다 — 외우면 되기 때문.
3. id 임베딩은 이 규모에서 득도 실도 없다(드롭아웃 덕에 해가 없음). 데이터가 쌓이면 종 고유의 운용(메타)을 담는 자리로 쓴다.

재현: `python tools/feasibility.py prep && python tools/feasibility.py run` (PC 에서는 스텝·망 크기를 키움).
