# 포켓몬 챔피언스 배틀 AI — 전체 구조 재설계안

> 대상: 포켓몬 챔피언스 (쇼다운 `champions` 모드) 싱글 6→3(BSS)·더블 6→4(VGC), 레벨 50, SP 0~32·합 66, 메가 1회, 테라스탈 없음.
> 목표: **엔트리(6마리 = 종·특성·도구·성격·SP·기술) → 상대 6마리를 본 뒤 선출·선봉 → 교체가 있는 실제 배틀** 전부를 하나의 프로그램이 맡고, 그 전부를 알파고 제로처럼 스스로 배우며, 쇼다운 봇을 이기고 사람에게도 강하고, 패치에 처음부터 다시 배우지 않고 따라가는 것.
> 이 문서는 지금 코드(2026-10-15 시점)를 실제로 읽고 측정한 것을 근거로, 무엇이 안일한지와 무엇으로 바꿔야 하는지를 적습니다. 숫자는 가능한 한 이 저장소의 로그·기록에서 직접 쟀습니다.

## 1. 지금 설계의 비판적 평가

### 1.1 평가가 통계적으로 의미가 없습니다 (가장 먼저 고칠 것)

이항 승률의 표준오차 SE = √(p(1−p)/n), p≈0.5 기준:

| 판 수 n | SE | 95% 구간 폭 | 지금 어디서 쓰이나 |
|---|---|---|---|
| 10 | ±15.8%p | ±31%p | `tools/overnight.py evaluate()` 기본 AI 상대 `max(10, n//2)` (회차 1 로그: 9/10, 5/10, 6/10) |
| 16 | ±12.5%p | ±24.5%p | 회차 1 "지금 최고 상대 8/16 = 50%" |
| 40 | ±7.9%p | ±15.5%p | README 실력표 전부, `tools/arena.py` 기본 |
| 60 | ±6.5%p | ±12.6%p | overnight 게이트 (35/60 = 58% → **채택**). z = 1.29, 단측 p ≈ 0.10 |
| 200 | ±3.5%p | ±6.9%p | `train_bring` 선출망 교체 (≥52% 기준 — 52% 는 1σ 안) |
| 400 | ±2.5%p | ±4.9%p | 없음 |
| 1,067 | ±1.5%p | ±3.0%p | 없음 |

- **게이트 55%/60판**은 "진짜 50% 짜리 신경망"을 약 22% 확률로 채택하고, "진짜 55% 짜리"를 절반 가까이 떨어뜨립니다. 회차 2 채택·회차 3 기각은 둘 다 노이즈로 설명됩니다.
- **파티 최적화(`engine/teamopt.py`)**: 상대 8팀 × 4×4 선출 셀 × 셀당 2판 = 256 플레이아웃으로 낸 내시값의 평균에 **+0.5%p 오르면 채택**. 셀 하나가 2판 평균(SE ±35%p)이고 내시값은 그 최대·최소를 고르므로 편향까지 있습니다. "깨비물거미 SP 변경 → 43.8% → 54.1%" 는 측정이 아니라 잡음입니다. 게다가 `games*2` 로 "확인"하지만 상대·난수가 고정이라 같은 잡음을 두 번 봅니다.
- **선출망 `bringnet` 173/300 = 57.7%** 는 SE ±2.9%p 로 그나마 유의하지만(p≈0.004), 배틀 AI 가 선생님일 때의 결과입니다 — 탐색 AI 와 조합하면 달라질 수 있습니다.
- **팀 레벨 승률 비교**에는 ±3%p 해상도가 필요하므로 매치업당 ≥1,000판, 아니면 SPRT 로 평균 ~400판에 끝내야 합니다.

### 1.3 수읽기(`engine/search.py` + `tools/ps_search.js`)의 한계

### 1.4 상대 세트 추정(`engine/belief.py`)

- 포켓몬마다 **독립**으로 사용률 → 기술 4개를 뽑습니다. 팀 문맥(동료·메가 보유·날씨 설치자 유무)과 드러난 다른 포켓몬 정보가 반영되지 않습니다.
- 데미지로 좁히기(`advisor.narrow_by_observations`)는 조언 탭에만 있고 탐색 세계 추출에는 없습니다.
- 아직 안 나온 포켓몬은 사용률로 뽑는데, 실제로는 **상대의 선출도 매치업에 따라 결정**됩니다(1.5 선출 예측과 같은 문제).
- 스피드(SP·성격)는 역할 사전(`ROLE_SPREADS`)뿐 — "스카프인가"의 사후 추정이 없습니다. 스피드 관계 오판이 BSS 에서 가장 흔한 패인입니다.

### 1.5 선출(`engine/bring.py`, `engine/bringnet.py`)

- 틀(선출×선출 행렬 → 내시)은 맞습니다. 문제는 **행렬을 어떻게 채우느냐**입니다.
  - `bringnet`: 32개 손변수(1:1 상성표 G 의 요약 + 시너지 플래그 16개), (32,16) MLP. 1:1 상성표는 본질적으로 가법적이라 "조합"이 안 보이고, 시너지 플래그는 열거한 것만 봅니다.
  - 라벨: 판당 (내 선출, 상대 선출, 승패) **1비트** → 60×60 중 1칸. 5.4천 표본으로 3,600칸짜리 함수를 배우는 셈 — 토큰 과적합은 데이터 문제입니다.
  - 상대 세트는 `typical_set`(최빈 세트) 고정 — 분포가 아니라 점추정.
- `bring.recommend`: 후보 10×10 만 플레이아웃(상대 세계 6, 셀당 6판) — 역시 셀당 SE ±20%p.
- **상대 선출 예측**이 없습니다. 내시는 "상대가 완벽히 합리적"일 때의 안전수이고, 사람은 메타대로(사용률·리드율) 냅니다. 둘을 섞는 **제한된 내시응답(RNR)** 이 필요합니다.
- 선봉 선택이 선출과 함께 행렬의 행으로 들어가는 것은 맞습니다 (싱글 60 = C(6,3)×3, 더블 90 = C(6,4)×C(4,2)).

### 1.7 학습 루프·계산량(`tools/overnight.py`)

- 회차당 **240판**(기본) 생성 → 6,000판 중 최근 것으로 학습 → 60판 게이트. 밤 8시간에 생성되는 판이 수천 판인데 게이트에 쓰는 판은 그 1% — 거꾸로입니다.
- 가치 라벨 = 판 결과 1비트가 ~24 결정에 공유 → 1에폭 뒤 과적합(STUDY.md 가 이미 관측). **탐색 루트값을 섞은 부트스트랩 라벨**이 필요합니다.
- 정책 라벨 = 탐색 softmax(T=0.02) ≈ 원-핫 → 분포 정보가 없습니다. 루트 행렬게임의 혼합전략을 라벨로 써야 합니다.
- 리그 상대 비율이 고정(`search 0.3, net 0.15, heuristic 0.2 …`) — AlphaStar 의 PFSP(이기기 어려운 상대를 더 자주)가 없고, 과거 신경망 4개만.
- `engine/model.py`+`tools/train.py`(옛 Q/V 모델)와 `engine/nets.py`+`tools/overnight.py`(정책·가치망)가 **두 벌** — app.py 는 둘 다 import. 정리 대상.
- 샌드박스(4코어·GPU 없음·쇼다운 빌드 없음)에서는 학습 루프 자체를 돌릴 수 없고, 사용자 PC 에서도 `torch` 가 없으면 numpy CPU 학습으로 떨어집니다(로그 확인).

### 2.3 배틀 — 탐색 + 신경망

**결정 절차 (`engine/search.py` v2 + `tools/ps_search.js` v2)**

1. 믿음망에서 상대 숨은 정보를 **세계 W=8** 뽑습니다(팀 전체를 한 번에 — 동료 조건부). 관측된 데미지가 있으면 세계마다 가능도 가중치 w_k ∝ Π P(관측 데미지 | 세계) 로 **중요도 가중**(데미지 엔진으로 계산, `advisor.narrow_by_observations` 재사용).
2. 정책망으로 내 합법 행동 상위 **K_me=6**, 상대 행동 예측 헤드 + 상대 정책망(같은 망을 상대 시점으로)으로 **K_opp=6**.
3. 세계마다 6×6 결합 행동을 시뮬레이터에 **1턴** 적용(쇼다운 복제 36×8 = 288회, 턴당 ~3 ms → ~1초; 자기대전 생성 시에는 W=4·K=5 로 ~0.3초).
4. 리프 = 가치망 (288 상태를 **배치 1회**로 평가: JS 가 압축 상태를 돌려주고 파이썬이 토큰화 → 배치 추론). 초기 회차에는 가치망 0.5 + raceValue 0.5 로 혼합, 가치망이 게이트를 통과할수록 비중을 올립니다(설정값).
5. 가중 평균 행렬 M̄(6×6) 의 **영합 행렬게임을 풉니다**(`solve_matrix` 가상 플레이 → LP 로 교체 가능). 결과:
   - 내시 혼합전략 p*, 상대 혼합 q*.
   - **상대 모델 혼합**: q = (1−λ)·q* + λ·q_pred (q_pred = 상대 행동 예측 헤드). 기본 λ=0.3, 상대가 봇/기본 AI 로 판정되면(행동 예측 정확도 높음) λ↑.
   - 내 행동 = argmax_i (M̄ q)_i 를 p* 쪽으로 정규화한 **제한된 내시응답**(안전한 착취).
6. 중요 상태(행렬 값 분산이 크거나 남은 마리 ≤2)에서는 깊이 2 로 확장: 1턴 뒤 상위 3×3 셀에 대해 다시 6×6 (최대 2,592 복제, 실전 모드에서만, 예산 `budgetMs`).
7. 기록: 루트 p*(정책 라벨), 루트값 v_root(가치 부트스트랩), 상대 q*, 세계 가중치.

**긴 호흡 전략은 어떻게 다루나**

| 전략 | 깊이로 못 푸는 이유 | 처리 |
|---|---|---|
| 스톨(맹독+보호+회복) | 수십 턴 | 가치망이 "맹독 걸린 상대·내 회복기·대타" 상태의 승률을 학습. 전역 토큰의 `raceValue` 가 초기 힌트 |

### 2.4 믿음(상대 세트 추정) v2

- `engine/belief.py` 의 후보 체계는 유지하되 **사전확률을 믿음망 출력으로 교체**합니다. 믿음망 입력: 상대 6마리 종 토큰(물리량) + 드러난 것(기술·도구·특성·메가·관측 스피드 순서·관측 데미지 구간) + 내 팀(상대가 나를 보고 고른 세트일 수 있으므로). 출력: 포켓몬마다 기술 보유 확률(학습셋 위), 도구 분포, 특성, SP/성격 **8구간 스피드 클래스**(예: 최속·준속·무보정·내구 등) + 스카프 확률.
- 정답: 자기대전은 상대 세트 전부, 기보는 `|showteam|` 또는 판 종료 시 공개된 부분(부분 라벨 → 마스크 BCE).
- 세계 추출: 포켓몬마다 독립이 아니라 **팀 조건부 순차 샘플링**(먼저 뽑은 포켓몬의 세트를 입력에 넣고 다음 포켓몬 분포 재계산). "패리퍼 잔비 확정 → 브리두라스 일렉트로빔 확률↑" 가 데이터에서 나옵니다.
- 스피드 사후 추정: 관측된 행동 순서(누가 먼저 움직였나) 를 전부 기록해 **구간 제약**으로 쓰고, 데미지 관측으로 SP·도구를 좁힙니다(엔진). 믿음망 출력 × 제약 = 최종 분포.

### 2.5 선출·선봉 v2

- **행렬망**: 팀 인코더(내 6 + 상대 6 토큰, 2층 d=128) → 선출 i 임베딩 = 선택된 3(4) 토큰의 합 + 선봉 위치 임베딩, 상대 j 도 동일 → M(i,j) = σ(g(e_i, e_j, 문맥) − g(e_j, e_i, 문맥)) (반대칭 유지). 한 매치업에서 60×60 전체를 **한 배치**로 계산(ms).
- **조밀 지도(핵심 변화)**: 매치업마다 (i,j) 전부에 대해 "선출 후 1턴 상태"(선봉 필드, 나머지 벤치, HP 100%)를 만들고 **배틀 가치망**으로 세계 W=8 평균 승률을 매깁니다 → 3,600(8,100)칸 라벨 / 매치업. GPU 배치로 매치업당 ~1.5초. 라벨 수가 판당 1비트에서 **매치업당 수천 개**로 늘어 토큰 모델이 과적합하지 않습니다.
- **희소 보정**: 실제 선출 쌍의 승패 BCE(가중치 1.0) + 조밀 MSE(가중치 0.3). 가치망이 편향돼도 실제 결과로 바로잡힙니다.
- **상대 선출 예측 q_h**: 사람 기보의 (상대 6, 내 6 → 상대가 낸 선출)로 학습하는 헤드(같은 팀 인코더). 기본값은 사용률·리드율 사전확률.
- 결정: M 의 내시 (p*, q*) 를 구한 뒤 q = (1−λ)q* + λ q_h (기본 λ=0.5, 사람 상대일 때) 에 대한 최선응답을 p* 로 정규화(RNR). 안전 선출(최악 보장)과 메타 최선 선출을 함께 표시(UI 유지).
- 평가: (a) 같은 배틀 AI 로 선출만 다르게 SPRT, (b) 사람 기보 홀드아웃에서 상대 선출 top-5 적중률(사용률 기준선 대비), (c) 조밀 라벨과 실제 결과의 보정(Brier).

### 2.6 파티 — 시즌 합법 전체 공간에서 PSRO

#### 공간과 합법성

| 변수 | 공간 | 생성·제약 |
|---|---|---|
| 종 | 합법 비메가 271 (+ 메가 폼 76 은 도구로 결정) | **쇼다운 `TeamValidator`** 를 `ps_bridge.js` 에 `validate` op 로 노출 — 포맷 밴리스트·종 클로즈·도구 클로즈·메가 규칙을 그대로 적용. 사용률 목록은 **사전확률일 뿐 제한이 아님** |
| 특성 | ≤3 | 학습셋 |
| 도구 | 148 (실질 ~45) | 도구 클로즈 |
| 성격·SP | 25 × (66점을 6칸 0~32 로) | **목적형 배분 생성기**: 스피드 벤치마크(상대 집단의 실스피드 분포에서 "X 보다 1 빠르게" 후보 ~10개) × 화력/내구 템플릿 × 성격 → 종당 ~40 후보. 사용률 스프레드는 후보에 추가 |

- 세트 제안망은 기보·사용률 세트(지도) + PSRO 에서 **채택된 세트**(강화)로 학습합니다. 생성 다양성을 위해 온도 샘플링 + 사용률 밖 기술 15% 탐험.

#### PSRO 팀 리그 (`engine/psro.py`)

```
P ← 초기 집단 (아키타입 시드 8팀 + 사용률 동료표 기반 8팀 + 기보 상위 팀 8팀)
반복 g = 1..G:
  A ← 집단 내 대전 결과 행렬 (|P|×|P|, 각 칸 n판, Wilson 구간 저장)   ← 실제 배틀 AI(빠른 신경망 모드)
  σ ← A 의 내시 (가상 플레이/LP), 다양성용 rectified Nash 옵션
  BR 탐색: 진화 탐색 (개체 200 × 세대 30, 변이 = 세트 제안망·종 교체·아키타입 점프)
           적합도 = Σ_j σ_j · V_team(T, P_j)         ← 대리 가치망 (ms)
  검증: 상위 10 후보 × 각 300판 (상대는 σ 에서 추출) → Wilson 하한 > 0.5 인 것만 P 에 추가
  착취 가능성 e_g = max(검증 승률) − 0.5  (신뢰구간 포함)
  V_team 재학습 (새 A 칸 + 검증 결과로)
종료: e_g 의 상한이 ε=0.03 아래로 3세대 연속, 또는 시간 예산
```

- **V_team(T_me, T_opp)** = 팀 인코더 → 선출 행렬망의 내시값 회귀(2.5 와 같은 망, 헤드만 다름). 즉 "이 두 팀이 만나면 최적 선출끼리 승률이 얼마인가"를 ms 에 답합니다. 1마리가 바뀌면 12토큰 어텐션이 전부 바뀌므로 비가법적입니다.
- **저격의 원리적 처리**: BR 탐색은 σ(현재 집단의 혼합)를 가장 잘 잡는 팀을 찾습니다. 드래곤 쏠림이면 얼음·페어리 팀이 BR 로 나오고 다음 세대 σ 가 그것을 반영합니다. "10팀 승률" 대신 **e_g(최선응답 이득)** 가 "모든 경우를 다 봤는가"의 지표입니다.
- **커버리지**: 엔진 계산 아키타입 태그(비·쾌청·모래·설경·트릭룸·순풍·스톨·배턴·하이퍼오펜스·밸런스; `bringnet.roles` 재사용)로 집단을 군집화하고, 군집별로 "σ 가 그 군집 최강팀에게 지는 정도"를 표로 냅니다. 모든 군집에서 ≥45% 가 목표.
- **사람 메타 압력**: 기보에서 추출한 팀 분포를 고정 플레이어 "human-meta"로 집단에 넣고 σ 계산 시 가중치 0.3 을 보장 — 자기대전만의 이상한 메타로 흘러가지 않게.
- **사용자에게 주는 답**: σ 의 지지집합 = 추천 포트폴리오. 단일 추천 = argmax (0.5·σ 상대 가치 + 0.5·human-meta 상대 가치). 사용자의 보관함 제약은 BR 탐색의 후보 제한으로 처리(기존 UI 유지).
- 통계: A 의 칸당 n=100 으로 시작, σ 지지집합 칸은 400 까지 증분. 검증 300판 → SE ±2.9%p.

|---|---|---|---|

| 아키타입 8팀 × 2변형 (비·쾌청·모래·트릭룸·순풍·스톨·배턴·하이퍼오펜스) | 고정 팀 + 탐색 v2 조종 | 각 200 | 커버리지 — 특정 아키타입에 약한지 |
| 이전 최고 체크포인트 5개 | 자기 과거 | SPRT | 진전·망각 |
| human-meta 팀 분포 (기보) | 상대 팀만 고정, 봇 조종 | 400 | 사람 메타 적합 |
| 기보 홀드아웃 (행동 일치·선출 일치·승패 예측·믿음 정확도) | 오프라인 | 전체 | 사람 유사도, 보정 |
| PSRO 최선응답 이득 e_g | 오프라인+검증 | 300/후보 | 착취 가능성 |
| 실제 래더(수동) | 사람 | 가능한 만큼 | 최종 목표; GXE/Elo 기록 |

유의성: 두 조건 차이 Δ 를 보려면 n ≈ 2·(1.96+0.84)²·0.25/Δ² → Δ=5%p 에 ~1,570판(양쪽 합), Δ=10%p 에 ~390판. **40판으로는 ±15%p 차이만 보입니다.**

- 계산: 사용자 PC 에서 기준표 ~1만 판(선생님·신경망 모드 1초/판 → 8코어 20분; 탐색 모드는 200판×19 = 3,800판 ≈ 1.5시간). 샌드박스: 쇼다운 빌드(`tools/setup_showdown.py`) 후 100판 규모 연기 검사만.

### 1단계 — 변수 묶음 토큰 표현 + BC (2~3주)

- 새로: `engine/tokens.py` (하위 토큰 물리량; `montoken` 흡수), `engine/encoder.py` (numpy/ONNX 추론: 세트·팀·배틀 인코더, 헤드), `engine/encoder_torch.py` (학습), `engine/statetok.py` (BattleView 스냅숏 + 믿음 → 21토큰), `engine/data.py` (기록 → 텐서 캐시 `.npz`, 토큰은 기록 후 계산).
- 학습: 기존 자기대전 기록 + 기보(있으면)로 BC. 비교 대상: 현 319칸 MLP (같은 분할).
- **합격**: 홀드아웃 정책 CE·가치 BCE 모두 MLP 이하; **종 홀드아웃(20종)** 손실 증가 ≤10%; 세트 인코더 단위검사 — (테크니션, 불릿펀치) 세트 토큰과 (테크니션, 인파이트) 토큰의 "선공 화력" 선형 프로브 차이가 데이터 없이도 물리량에서 나옴; 신경망 단독 vs 선생님 SPRT ≥55% (현 50%).
- 계산: 3060 에서 300k 결정 BC 10에폭 ≈ 30분. 샌드박스: 2만 결정 numpy 소형(d=64) 연기 검사 ~20분.

### 2단계 — 탐색 v2 (루트 행렬게임 + 가치망 리프) (2주)

- 다시 씀: `tools/ps_search.js` — `matrixStep` op: (세계 W, 내 K, 상대 K) → 1턴 적용 → 압축 상태 배열 반환(복제 비용 측정·로그); `engine/search.py` — 토큰화·배치 가치·행렬게임·RNR·기록.
- `engine/bring.py solve_matrix`: LP(scipy 없으면 가상 플레이 유지, 반복 3k→10k 와 수렴 검사).
- **합격**: 탐색 v2(가치망 리프) vs 탐색 v1(raceValue 리프) SPRT ≥55%; vs 선생님 ≥80% (400판, 하한 >75%); 결정당 평균 시간 실전 모드 ≤2초, 생성 모드 ≤0.4초(8코어 PC 기준); 상대 모델 λ=0 과 λ=0.3 의 봇 상대 승률 차이 보고.
- 계산: 자기대전 생성 처리량 측정이 이 단계의 산출물. 목표 8작업자 ≥2,000판/시간.

### 3단계 — 믿음망 + 선출 v2 (2주)

- 새로: `engine/beliefnet.py` (헤드·팀 조건부 샘플러), `engine/bringnet2.py` (팀 인코더 행렬망, 조밀 라벨 생성 `dense_labels()`, 상대 선출 예측, RNR 결정).
- 고침: `engine/belief.py` 사전확률 교체, `engine/search.py` 세계 추출·데미지 가중.
- **합격**: 믿음 — 자기대전 홀드아웃에서 숨은 기술 top-4 적중률이 사용률 기준선 대비 +15%p, 스카프 판정 AUC ≥0.8; 선출 — 같은 배틀 AI 로 선출만 바꿔 SPRT ≥55% vs bringnet v1, 기보 상대 선출 top-5 적중률 > 사용률 기준선; 조밀 라벨 Brier 가 실제 결과 대비 ≤0.22.
- 계산: 조밀 라벨 1,500 매치업 40분(GPU).

### 4단계 — 팀 PSRO (3주)

- 새로: `engine/teamspace.py` (목적형 SP 생성기, 스피드 벤치마크 표, 후보 열거, validator 연결), `engine/setnet.py` (세트 제안망), `engine/teamvalue.py` (V_team 헤드), `engine/psro.py` (집단·A 행렬·σ·BR 진화 탐색·검증·착취 가능성), `userdata/population/{singles,doubles}/` (팀·A·σ·세대 기록), 리포트 `reports/teams.md`(σ 포트폴리오, 군집 커버리지, e_g 추이).
- 삭제: `engine/teamopt.py`. `app.py` 파티 탭은 PSRO 포트폴리오·보관함 제약 BR 호출로 교체.
- **합격**: e_g 상한이 세대 1 → 세대 10 에서 단조 감소하고 최종 ≤0.05; 군집 8개 모두에서 σ 가 ≥45%(200판, 하한 ≥40%); σ 지지집합 팀이 human-meta 팀 분포 상대 ≥55%(400판); 1마리 교체 민감도 검사 — V_team 이 "5마리 동일·1마리 다름" 쌍 100개에서 실제 시뮬 승률 차이와 상관 ≥0.6.
- 계산: 세대당 ~2시간(PC). 10세대 = 밤 5회 분량의 5단계 예산.

### 5단계 — 더블 (별도 트랙 D0~D4, 4장 끝의 표) 

- 더블은 싱글 1~4단계와 **병행하는 별도 트랙**입니다. 공유하는 것은 토큰 물리량·세트 인코더·탐색 골격·평가 도구뿐이고, 짝 인코더·결합 행동 헤드·매크로 후보·선출 짝 평가·벤치마크는 따로 만듭니다. 단계별 합격 기준과 계산량은 4.7 절 표에 있습니다.

### 6단계 — 밤샘 v2·연속 운영 (1주)

- `tools/overnight2.py`: 2.7 의 단계형 예산, PFSP, SPRT, 리허설, patch_diff 연동, 중단·재개; `reports/eval.md` 자동.
- **합격**: 무인 3밤 연속 실행, 체크포인트 Elo 단조 비감소(앵커 기준), 리포트에 CI·e_g·커버리지 포함.

## 부록 A. 통계 공식

- Wilson 95% 구간: 중심 (p + z²/2n)/(1 + z²/n), 반폭 z·√(p(1−p)/n + z²/4n²)/(1 + z²/n), z=1.96.
- SPRT (p0=0.50, p1=0.55, α=β=0.05): 판마다 LLR += ln(p1/p0) (승) 또는 ln((1−p1)/(1−p0)) (패); LLR ≥ ln((1−β)/α)=2.94 채택, ≤ ln(β/(1−α))=−2.94 기각. 기대 판 수 ~400~900.
- 두 조건 승률 차 Δ 검출(검정력 80%): n_각 ≈ 2·(1.96+0.84)²·p(1−p)/Δ².
