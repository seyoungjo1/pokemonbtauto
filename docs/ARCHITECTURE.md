# 포켓몬 챔피언스 배틀 AI — 전체 구조 재설계안

> 대상: 포켓몬 챔피언스 (쇼다운 `champions` 모드) 싱글 6→3(BSS)·더블 6→4(VGC), 레벨 50, SP 0~32·합 66, 메가 1회, 테라스탈 없음.
> 목표: **엔트리(6마리 = 종·특성·도구·성격·SP·기술) → 상대 6마리를 본 뒤 선출·선봉 → 교체가 있는 실제 배틀** 전부를 하나의 프로그램이 맡고, 그 전부를 알파고 제로처럼 스스로 배우며, 쇼다운 봇을 이기고 사람에게도 강하고, 패치에 처음부터 다시 배우지 않고 따라가는 것.
> 이 문서는 지금 코드(2026-10-15 시점)를 실제로 읽고 측정한 것을 근거로, 무엇이 안일한지와 무엇으로 바꿔야 하는지를 적습니다. 숫자는 가능한 한 이 저장소의 로그·기록에서 직접 쟀습니다.

## 1. 지금 설계의 비판적 평가

### 1.1 평가가 통계적으로 의미가 없습니다 (가장 먼저 고칠 것)

이항 승률의 표준오차 SE = √(p(1−p)/n), p≈0.5 기준:

| 판 수 n | SE | 95% 구간 폭 | 지금 어디서 쓰이나 |
|---|---|---|---|
| 10 | ±15.8%p | ±31%p | `tools/overnight.py evaluate()` 기본 AI 상대 `max(10, n//2)` (회차 1 로그: 9/10, 5/10, 6/10) |
| 16 | ±12.5%p | ±24.5%p | 회차 1 "지금 최고 상대 8/16 = 50%" |
| 40 | ±7.9%p | ±15.5%p | README 실력표 전부, `tools/arena.py` 기본 |
| 60 | ±6.5%p | ±12.6%p | overnight 게이트 (35/60 = 58% → **채택**). z = 1.29, 단측 p ≈ 0.10 |
| 200 | ±3.5%p | ±6.9%p | `train_bring` 선출망 교체 (≥52% 기준 — 52% 는 1σ 안) |
| 400 | ±2.5%p | ±4.9%p | 없음 |
| 1,067 | ±1.5%p | ±3.0%p | 없음 |

- **게이트 55%/60판**은 "진짜 50% 짜리 신경망"을 약 22% 확률로 채택하고, "진짜 55% 짜리"를 절반 가까이 떨어뜨립니다. 회차 2 채택·회차 3 기각은 둘 다 노이즈로 설명됩니다.
- **파티 최적화(`engine/teamopt.py`)**: 상대 8팀 × 4×4 선출 셀 × 셀당 2판 = 256 플레이아웃으로 낸 내시값의 평균에 **+0.5%p 오르면 채택**. 셀 하나가 2판 평균(SE ±35%p)이고 내시값은 그 최대·최소를 고르므로 편향까지 있습니다. "깨비물거미 SP 변경 → 43.8% → 54.1%" 는 측정이 아니라 잡음입니다. 게다가 `games*2` 로 "확인"하지만 상대·난수가 고정이라 같은 잡음을 두 번 봅니다.
- **선출망 `bringnet` 173/300 = 57.7%** 는 SE ±2.9%p 로 그나마 유의하지만(p≈0.004), 배틀 AI 가 선생님일 때의 결과입니다 — 탐색 AI 와 조합하면 달라질 수 있습니다.
- **팀 레벨 승률 비교**에는 ±3%p 해상도가 필요하므로 매치업당 ≥1,000판, 아니면 SPRT 로 평균 ~400판에 끝내야 합니다.

### 1.3 수읽기(`engine/search.py` + `tools/ps_search.js`)의 한계

| 항목 | 지금 | 왜 한계인가 |

측정된 92%/62%/72%(40판)는 신뢰구간을 감안하면 "기본 봇은 확실히 이긴다, 최대데미지·선생님은 이기는 쪽"입니다.

### 1.4 상대 세트 추정(`engine/belief.py`)

- 포켓몬마다 **독립**으로 사용률 → 기술 4개를 뽑습니다. 팀 문맥(동료·메가 보유·날씨 설치자 유무)과 드러난 다른 포켓몬 정보가 반영되지 않습니다.
- 데미지로 좁히기(`advisor.narrow_by_observations`)는 조언 탭에만 있고 탐색 세계 추출에는 없습니다.
- 아직 안 나온 포켓몬은 사용률로 뽑는데, 실제로는 **상대의 선출도 매치업에 따라 결정**됩니다(1.5 선출 예측과 같은 문제).
- 스피드(SP·성격)는 역할 사전(`ROLE_SPREADS`)뿐 — "스카프인가"의 사후 추정이 없습니다. 스피드 관계 오판이 BSS 에서 가장 흔한 패인입니다.

### 1.5 선출(`engine/bring.py`, `engine/bringnet.py`)

- 틀(선출×선출 행렬 → 내시)은 맞습니다. 문제는 **행렬을 어떻게 채우느냐**입니다.
  - `bringnet`: 32개 손변수(1:1 상성표 G 의 요약 + 시너지 플래그 16개), (32,16) MLP. 1:1 상성표는 본질적으로 가법적이라 "조합"이 안 보이고, 시너지 플래그는 열거한 것만 봅니다.
  - 라벨: 판당 (내 선출, 상대 선출, 승패) **1비트** → 60×60 중 1칸. 5.4천 표본으로 3,600칸짜리 함수를 배우는 셈 — 토큰 과적합은 데이터 문제입니다.
  - 상대 세트는 `typical_set`(최빈 세트) 고정 — 분포가 아니라 점추정.
- `bring.recommend`: 후보 10×10 만 플레이아웃(상대 세계 6, 셀당 6판) — 역시 셀당 SE ±20%p.
- **상대 선출 예측**이 없습니다. 내시는 "상대가 완벽히 합리적"일 때의 안전수이고, 사람은 메타대로(사용률·리드율) 냅니다. 둘을 섞는 **제한된 내시응답(RNR)** 이 필요합니다.
- 선봉 선택이 선출과 함께 행렬의 행으로 들어가는 것은 맞습니다 (싱글 60 = C(6,3)×3, 더블 90 = C(6,4)×C(4,2)).

### 1.7 학습 루프·계산량(`tools/overnight.py`)

- 회차당 **240판**(기본) 생성 → 6,000판 중 최근 것으로 학습 → 60판 게이트. 밤 8시간에 생성되는 판이 수천 판인데 게이트에 쓰는 판은 그 1% — 거꾸로입니다.
- 가치 라벨 = 판 결과 1비트가 ~24 결정에 공유 → 1에폭 뒤 과적합(STUDY.md 가 이미 관측). **탐색 루트값을 섞은 부트스트랩 라벨**이 필요합니다.
- 정책 라벨 = 탐색 softmax(T=0.02) ≈ 원-핫 → 분포 정보가 없습니다. 루트 행렬게임의 혼합전략을 라벨로 써야 합니다.
- 리그 상대 비율이 고정(`search 0.3, net 0.15, heuristic 0.2 …`) — AlphaStar 의 PFSP(이기기 어려운 상대를 더 자주)가 없고, 과거 신경망 4개만.
- `engine/model.py`+`tools/train.py`(옛 Q/V 모델)와 `engine/nets.py`+`tools/overnight.py`(정책·가치망)가 **두 벌** — app.py 는 둘 다 import. 정리 대상.
- 샌드박스(4코어·GPU 없음·쇼다운 빌드 없음)에서는 학습 루프 자체를 돌릴 수 없고, 사용자 PC 에서도 `torch` 가 없으면 numpy CPU 학습으로 떨어집니다(로그 확인).

### 2.2 표현 — 학습 단위는 종(種)이 아니라 구성 요소입니다

> 원칙: **"마리 수에 대한 신경망"이 아니라, 도구·특성·기믹·SP(능력치)·기술·타입 각각에 대한 신경망을 배우고, 그것을 묶은 것이 포켓몬일 뿐이다.** 포켓몬은 이름이 아니라 요소 토큰 ~10개의 어텐션 결과이고, 팀은 포켓몬 벡터 6개(+상대 6개)의 어텐션 결과이며, 팀 가치망·선출망·배틀망은 이 인코더 하나를 공유합니다.

이 원칙이 주는 것: (a) 요소가 바뀌거나 새로 생기면(패치) 그 요소 토큰만 고치면 되고, (b) "테크니션×불릿펀치" 같은 관계가 **포켓몬 안의 요소 어텐션 층**에서 학습되어 그 특성·그 기술을 가진 **어떤 종**에도 옮겨지며, (c) 요소 수가 작아(타입 18·특성 316·도구 148·기술 500·종 347) 임베딩 파라미터가 2만 개 남짓이라 데이터가 적어도 과적합이 제한됩니다.

#### 2.2.1 요소 사전 — 요소마다 "엔진 서술자(고정 차원) + 작은 학습 임베딩"

#### 2.2.2 포켓몬 = 요소 토큰 ~10개의 어텐션

```

   └── 요소 인코더: 트랜스포머 2층 d=128 4헤드 ──┐
       출력: 포켓몬 벡터 = [MON] (128)             │   기술 j 출력 벡터 (128) ← 정책 헤드의 "기술 j 행동" 표현
```

- **관계는 이 층에서 학습됩니다.** 특성 토큰이 기술 토큰을 보고(테크니션→불릿펀치 위력 60 이하), 도구 토큰이 특성을 보고(곡예→소모 도구), 기술 토큰이 날씨 설치 특성을 보고(일렉트로빔→잔비) 가중치를 바꿉니다. 특정 종에 묶이지 않으므로 같은 조합을 가진 처음 보는 종에도 그대로 적용됩니다.
- **엔진이 잰 배율은 보조 입력**입니다: 기술 토큰 j 의 서술자에 "이 세트에서의 특성 배율·도구 배율·자속·18 방어타입 상대 화력"(`montoken.move_multipliers`)을 덧붙입니다. 신경망이 배율 자체를 외울 필요는 없고, 배율이 **언제 가치로 이어지는가**(스피드·상대 분포·턴 수)를 배우는 데 집중합니다. 날씨 이득(`weather_profile`)·템포(`tempo_profile`)도 같은 방식으로 [MON] 토큰의 서술자가 됩니다.
- 정책 헤드가 "기술 j 사용"의 행동 임베딩으로 **그 기술 토큰의 인코더 출력**을 쓰므로, 행동 표현도 요소 기반입니다(교체는 대상 포켓몬 벡터, 메가는 기믹 토큰 출력).
- 자기대전·기보에서는 세트가 전부 알려지므로 요소 토큰이 확정값이고, 상대 포켓몬은 2.4 의 믿음 분포로 **부드러운 요소 토큰**(기술 후보 상위 8개의 확률 가중 합, 도구·특성 혼합)을 만듭니다. 즉 "모르는 요소"도 같은 층을 통과합니다.

#### 2.2.3 팀 = 포켓몬 벡터 6(+6)의 어텐션

- 팀 인코더: 내 6 + 상대 6 포켓몬 벡터 + 편 임베딩 + [TEAM] 토큰, 2층 d=128. 더블은 여기에 짝 토큰(4.2)이 더해집니다.
- "5마리 같고 1마리 다르면 다른 팀"은 이 층의 어텐션으로 표현됩니다 — 바뀐 1마리가 나머지 5마리의 표현을 모두 바꿉니다. 1:1 상성표(가법)와의 결정적 차이입니다.

#### 2.2.4 공유 인코더, 세 가지 헤드

| 망 | 입력 | 공유 | 고유 헤드 |
|---|---|---|---|
| 팀 가치망 V_team | 내 6 + 상대 6 (세트 전부 알거나 믿음) | 요소·포켓몬·팀 인코더 | [TEAM] → 내시값 회귀 |
| 선출망 M(i,j) | 같음 | 같음 | 선출 임베딩(선택 포켓몬 벡터 합 + 선봉 위치) → 반대칭 점수 |
| 배틀망 | 12 포켓몬 벡터 ⊕ 동적 상태 + 전역 + 역사 | 요소·포켓몬 인코더 (+팀 인코더 가중치로 초기화) | 정책·가치·믿음·상대 행동 |

요소·포켓몬 인코더의 가중치는 세 망이 **문자 그대로 공유**(같은 파라미터)합니다. 밤샘 학습은 세 손실을 번갈아(또는 합쳐) 최적화하고, 저장은 인코더 하나 + 헤드 셋입니다.

#### 2.2.5 보조 손실 — 엔진 계산값 예측 (= 엔진으로 하는 사전학습)

엔진은 라벨을 **무한히** 만들 수 있습니다. 대전 데이터가 적을 때 요소 임베딩에 의미를 주는 가장 싼 방법입니다. 무작위 세트 쌍(전 종·전 요소에서 균등 추출, 사용률과 무관)에 대해:

| 보조 목표 | 예측 위치 | 라벨(엔진) | 손실·가중치 |
|---|---|---|---|
| 기술 배율 | 기술 j 출력 | log(특성 배율 × 도구 배율 × 자속) | MSE 0.1 |
| 기대 데미지 % · 처치 확률 | (포켓몬 A 벡터, 포켓몬 B 벡터, 기술 j 출력) | `damage.calc` 16단계 평균 %, KO 확률 (날씨·필드·랭크 무작위 조건 포함) | MSE + BCE 0.2 |
| 행동 순서 | (A, B) + 조건 토큰(트릭룸·순풍·마비·끈적끈적네트) | 누가 먼저 (엔진 스피드 계산) | BCE 0.1 |
| 타입 상성 | (타입 토큰, 타입 토큰) | 배율 log2 | MSE 0.05 |
| 날씨·템포 프로필 | [MON] | `weather_profile` 8, `tempo_profile` 18 | MSE 0.05 |
| 레이스 가치 | 배틀 전역 토큰 | `raceValue` (초기 회차만) | MSE 0.05 |

- 사전학습: 대전 데이터 없이 보조 손실만으로 인코더를 50만 세트 쌍 정도 학습(3060 에서 10분 안팎) → 그 가중치에서 BC·자기대전 미세조정. 합격선: 데미지 % 예측 R² ≥0.95, 행동 순서 정확도 ≥0.98, 처음 보는 종·기술 홀드아웃에서도 R² ≥0.9.
- 미세조정 중에도 보조 손실을 작은 가중치로 유지해 표현이 대전 데이터의 편향으로 무너지지 않게 합니다.

#### 2.2.6 처음 보는 요소·패치 → 수술

| 변화 | 처리 |
|---|---|
| 수치 변경(위력·종족값·배율) | 서술자가 자동으로 바뀜. 임베딩은 그대로. 짧은 미세조정 |
| 새 요소(새 기술·특성·도구·종·메가 폼) | 서술자 계산 → 임베딩 = 서술자 공간 k=5 최근접 요소 임베딩 평균 (+ 잔차 0) → `patch_diff` focus 로 그 요소 포함 팀 대전 ↑ → 리허설 섞어 미세조정 |
| 새 처리기 이름(새 효과 종류) | 다중-핫 칸 추가 → 사영층 열 0 초기화 수술 (출력 보존 검사) |
| 새 기믹(새 행동 종류) | 토큰 종류 1개 추가(종류 임베딩 0), `legal_choices` 확장, 정책 헤드 행동 종류 추가, 수술 + 리허설 |
| 레귤레이션(사용 가능 종 변경) | 쇼다운 validator 가 팀 공간을 바꿈. 표현은 변경 없음 |

검증: **요소 홀드아웃** — 학습에서 종 20·기술 30·특성 10·도구 5 를 빼고, 그것들이 포함된 판에서 정책·가치 손실 증가 ≤10%, 보조 목표 R² ≥0.9.

#### 2.2.7 데이터가 적을 때의 과적합 대책 (요약)

1. 서술자는 고정 차원, 임베딩은 작게(8~16): 임베딩 파라미터 총합 ≈ 18·8 + (316+148+500+347)·16 ≈ **2.1만** — 인코더(≈1.5M)에 비해 무시할 수준이라 "이름 암기" 용량이 거의 없습니다.
2. 임베딩 드롭아웃(종 0.5·나머지 0.3) + 임베딩 가중치 감쇠 1e-3: 서술자만으로도 답을 내게 강제.
3. 엔진 보조 손실·사전학습(2.2.5): 라벨이 무한한 과제로 표현을 먼저 고정.
4. 증강: 기술 순서 섞기, 팀 순서 섞기, p1↔p2 미러, **SP 재샘플**(같은 세트의 SP 를 바꾸고 실능력치를 엔진으로 다시 계산 — 가치 라벨은 유지하되 보조 라벨은 재계산).
5. 판 단위 분할·조기 종료, 가치 라벨 부트스트랩(2.7) 으로 1비트 라벨 과적합 완화.
6. 파라미터 예산: 요소 인코더 0.4M, 팀 인코더 0.4M, 배틀 인코더 1.8M, 헤드 0.3M ≈ 2.9M. 데이터가 30만 결정 이하면 d=96 프로필로 자동 축소.

### 2.3 배틀 — 탐색 + 신경망

**결정 절차 (`engine/search.py` v2 + `tools/ps_search.js` v2)**

1. 믿음망에서 상대 숨은 정보를 **세계 W=8** 뽑습니다(팀 전체를 한 번에 — 동료 조건부). 관측된 데미지가 있으면 세계마다 가능도 가중치 w_k ∝ Π P(관측 데미지 | 세계) 로 **중요도 가중**(데미지 엔진으로 계산, `advisor.narrow_by_observations` 재사용).
2. 정책망으로 내 합법 행동 상위 **K_me=6**, 상대 행동 예측 헤드 + 상대 정책망(같은 망을 상대 시점으로)으로 **K_opp=6**.
3. 세계마다 6×6 결합 행동을 시뮬레이터에 **1턴** 적용(쇼다운 복제 36×8 = 288회, 턴당 ~3 ms → ~1초; 자기대전 생성 시에는 W=4·K=5 로 ~0.3초).
4. 리프 = 가치망 (288 상태를 **배치 1회**로 평가: JS 가 압축 상태를 돌려주고 파이썬이 토큰화 → 배치 추론). 초기 회차에는 가치망 0.5 + raceValue 0.5 로 혼합, 가치망이 게이트를 통과할수록 비중을 올립니다(설정값).
5. 가중 평균 행렬 M̄(6×6) 의 **영합 행렬게임을 풉니다**(`solve_matrix` 가상 플레이 → LP 로 교체 가능). 결과:
   - 내시 혼합전략 p*, 상대 혼합 q*.
   - **상대 모델 혼합**: q = (1−λ)·q* + λ·q_pred (q_pred = 상대 행동 예측 헤드). 기본 λ=0.3, 상대가 봇/기본 AI 로 판정되면(행동 예측 정확도 높음) λ↑.
   - 내 행동 = argmax_i (M̄ q)_i 를 p* 쪽으로 정규화한 **제한된 내시응답**(안전한 착취).
6. 중요 상태(행렬 값 분산이 크거나 남은 마리 ≤2)에서는 깊이 2 로 확장: 1턴 뒤 상위 3×3 셀에 대해 다시 6×6 (최대 2,592 복제, 실전 모드에서만, 예산 `budgetMs`).
7. 기록: 루트 p*(정책 라벨), 루트값 v_root(가치 부트스트랩), 상대 q*, 세계 가중치.

| 셋업 스윕 (칼춤·용춤·배북, +6 핫삼 불릿펀치) | 2~3턴 뒤 폭발 | 랭크·선공기 화력(`tempo_profile`)이 포켓몬 벡터의 서술자에 있고, 행렬게임이 "셋업 vs 즉시 공격"을 동시행동으로 평가. 가치망이 +2 상태를 높게 봄 |
| 배턴터치 체인 | 교체 뒤 가치 | 역사 토큰 + 벤치 토큰(어떤 포켓몬이 받을지) — 정책 헤드의 교체 대상 토큰이 랭크 이월을 봄 |
| 트릭룸·순풍·날씨 턴 | 남은 턴 수 | 전역 토큰에 남은 턴 명시, 리프가 그 턴 안에 있는지 가치망이 학습 |
| 장판(스텔스록·끈적끈적네트) | 선공기엔 무관 | 기술 토큰의 우선도·장판 서술자 + 전역 장판 변수; 믿음망이 "기합의띠 무효" 상황 반영 |
| 대타·보호 패턴 | 상대 반응 | 역사 토큰(보호 연속), 상대 행동 예측 헤드 |

**더블**은 2.3 의 틀(세계 × 루트 행렬게임 × 가치망 리프)을 공유하지만 후보 생성·표현·선출·평가가 모두 다르므로 **4장에서 별도로** 설계합니다.

### 2.4 믿음(상대 세트 추정) v2

- `engine/belief.py` 의 후보 체계는 유지하되 **사전확률을 믿음망 출력으로 교체**합니다. 믿음망 입력: 상대 6마리 종·타입 토큰(서술자) + 드러난 것(기술·도구·특성·메가·관측 스피드 순서·관측 데미지 구간) + 내 팀(상대가 나를 보고 고른 세트일 수 있으므로). 출력: 포켓몬마다 기술 보유 확률(학습셋 위), 도구 분포, 특성, SP/성격 **8구간 스피드 클래스**(예: 최속·준속·무보정·내구 등) + 스카프 확률.
- 정답: 자기대전은 상대 세트 전부, 기보는 `|showteam|` 또는 판 종료 시 공개된 부분(부분 라벨 → 마스크 BCE).
- 세계 추출: 포켓몬마다 독립이 아니라 **팀 조건부 순차 샘플링**(먼저 뽑은 포켓몬의 세트를 입력에 넣고 다음 포켓몬 분포 재계산). "패리퍼 잔비 확정 → 브리두라스 일렉트로빔 확률↑" 가 데이터에서 나옵니다.
- 스피드 사후 추정: 관측된 행동 순서(누가 먼저 움직였나) 를 전부 기록해 **구간 제약**으로 쓰고, 데미지 관측으로 SP·도구를 좁힙니다(엔진). 믿음망 출력 × 제약 = 최종 분포.

### 2.5 선출·선봉 v2

- **행렬망**: 팀 인코더(내 6 + 상대 6 토큰, 2층 d=128) → 선출 i 임베딩 = 선택된 3(4) 토큰의 합 + 선봉 위치 임베딩, 상대 j 도 동일 → M(i,j) = σ(g(e_i, e_j, 문맥) − g(e_j, e_i, 문맥)) (반대칭 유지). 한 매치업에서 60×60 전체를 **한 배치**로 계산(ms).
- **조밀 지도(핵심 변화)**: 매치업마다 (i,j) 전부에 대해 "선출 후 1턴 상태"(선봉 필드, 나머지 벤치, HP 100%)를 만들고 **배틀 가치망**으로 세계 W=8 평균 승률을 매깁니다 → 3,600(8,100)칸 라벨 / 매치업. GPU 배치로 매치업당 ~1.5초. 라벨 수가 판당 1비트에서 **매치업당 수천 개**로 늘어 토큰 모델이 과적합하지 않습니다.
- **희소 보정**: 실제 선출 쌍의 승패 BCE(가중치 1.0) + 조밀 MSE(가중치 0.3). 가치망이 편향돼도 실제 결과로 바로잡힙니다.
- **상대 선출 예측 q_h**: 사람 기보의 (상대 6, 내 6 → 상대가 낸 선출)로 학습하는 헤드(같은 팀 인코더). 기본값은 사용률·리드율 사전확률.
- 결정: M 의 내시 (p*, q*) 를 구한 뒤 q = (1−λ)q* + λ q_h (기본 λ=0.5, 사람 상대일 때) 에 대한 최선응답을 p* 로 정규화(RNR). 안전 선출(최악 보장)과 메타 최선 선출을 함께 표시(UI 유지).
- 평가: (a) 같은 배틀 AI 로 선출만 다르게 SPRT, (b) 사람 기보 홀드아웃에서 상대 선출 top-5 적중률(사용률 기준선 대비), (c) 조밀 라벨과 실제 결과의 보정(Brier).

### 2.6 파티 — 시즌 합법 전체 공간에서 PSRO

#### 공간과 합법성

| 변수 | 공간 | 생성·제약 |
|---|---|---|
| 종 | 합법 비메가 271 (+ 메가 폼 76 은 도구로 결정) | **쇼다운 `TeamValidator`** 를 `ps_bridge.js` 에 `validate` op 로 노출 — 포맷 밴리스트·종 클로즈·도구 클로즈·메가 규칙을 그대로 적용. 사용률 목록은 **사전확률일 뿐 제한이 아님** |
| 특성 | ≤3 | 학습셋 |
| 도구 | **73** + 그 종의 메가스톤 (돌격조끼·구애머리띠/안경·울퉁불퉁멧·화염/맹독구슬 없음) | 도구 클로즈. 2.2.8 참조 |
| 성격·SP | 25 × 10,008,272 (66점을 6칸 0~32 로 나누는 정수해) | **목적형 배분 생성기**: 스피드 벤치마크(상대 집단의 실스피드 분포에서 "X 보다 1 빠르게" 후보 ~10개) × 화력/내구 템플릿 × 성격 → 종당 ~40 후보. 사용률 스프레드는 후보에 추가 |
| 기술 4 | C(학습셋 ~66, 4) ≈ 72만 | **세트 제안망** p(기술 집합 | 종, 특성, 도구, 동료 5) 자기회귀 샘플링 + 엔진 필터(공격기 ≥1, 자속·커버리지 점수). 사용률 없는 종도 요소 서술자 입력이라 동작 |

- 세트 제안망은 기보·사용률 세트(지도) + PSRO 에서 **채택된 세트**(강화)로 학습합니다. 생성 다양성을 위해 온도 샘플링 + 사용률 밖 기술 15% 탐험.

#### PSRO 팀 리그 (`engine/psro.py`)

```
P ← 초기 집단 (아키타입 시드 8팀 + 사용률 동료표 기반 8팀 + 기보 상위 팀 8팀)
반복 g = 1..G:
  A ← 집단 내 대전 결과 행렬 (|P|×|P|, 각 칸 n판, Wilson 구간 저장)   ← 실제 배틀 AI(빠른 신경망 모드)
  σ ← A 의 내시 (가상 플레이/LP), 다양성용 rectified Nash 옵션
  BR 탐색: 진화 탐색 (개체 200 × 세대 30, 변이 = 세트 제안망·종 교체·아키타입 점프)
           적합도 = Σ_j σ_j · V_team(T, P_j)         ← 대리 가치망 (ms)
  검증: 상위 10 후보 × 각 300판 (상대는 σ 에서 추출) → Wilson 하한 > 0.5 인 것만 P 에 추가
  착취 가능성 e_g = max(검증 승률) − 0.5  (신뢰구간 포함)
  V_team 재학습 (새 A 칸 + 검증 결과로)
종료: e_g 의 상한이 ε=0.03 아래로 3세대 연속, 또는 시간 예산
```

- **V_team(T_me, T_opp)** = 팀 인코더 → 선출 행렬망의 내시값 회귀(2.5 와 같은 망, 헤드만 다름). 즉 "이 두 팀이 만나면 최적 선출끼리 승률이 얼마인가"를 ms 에 답합니다. 1마리가 바뀌면 12토큰 어텐션이 전부 바뀌므로 비가법적입니다.
- **저격의 원리적 처리**: BR 탐색은 σ(현재 집단의 혼합)를 가장 잘 잡는 팀을 찾습니다. 드래곤 쏠림이면 얼음·페어리 팀이 BR 로 나오고 다음 세대 σ 가 그것을 반영합니다. "10팀 승률" 대신 **e_g(최선응답 이득)** 가 "모든 경우를 다 봤는가"의 지표입니다.
- **커버리지**: 엔진 계산 아키타입 태그(비·쾌청·모래·설경·트릭룸·순풍·스톨·배턴·하이퍼오펜스·밸런스; `bringnet.roles` 재사용)로 집단을 군집화하고, 군집별로 "σ 가 그 군집 최강팀에게 지는 정도"를 표로 냅니다. 모든 군집에서 ≥45% 가 목표.
- **사람 메타 압력**: 기보에서 추출한 팀 분포를 고정 플레이어 "human-meta"로 집단에 넣고 σ 계산 시 가중치 0.3 을 보장 — 자기대전만의 이상한 메타로 흘러가지 않게.
- **사용자에게 주는 답**: σ 의 지지집합 = 추천 포트폴리오. 단일 추천 = argmax (0.5·σ 상대 가치 + 0.5·human-meta 상대 가치). 사용자의 보관함 제약은 BR 탐색의 후보 제한으로 처리(기존 UI 유지).
- 통계: A 의 칸당 n=100 으로 시작, σ 지지집합 칸은 400 까지 증분. 검증 300판 → SE ±2.9%p.

## 4. 더블(VGC 6→4) — 별도 설계

### 4.1 왜 싱글의 확장으로는 안 되는가

더블은 **턴마다 2v2 동시행동**이고, 한 포켓몬의 가치가 "혼자 얼마나 치는가"가 아니라 "짝이 무엇을 하게 해 주는가"로 정해집니다. 예: 파밀리쥐(따라와·분노의앞니·앞질러가기)나 브리무음(볼부비부비 마비·앞질러가기·트릭룸)은 1:1 로는 아무것도 못 잡지만, 유도로 한카리아스의 지진을 받아 주고 마비로 스피드를 뒤집어 **짝이 한카리아스를 잡게** 합니다. 이 로스터에서 그런 역할을 가진 포켓몬: 따라와 8종(파밀리쥐·픽시·라이츄…), 분노가루 25종(불카모스 8.6%·그우린차 7.5%), 속이기 26종(포푸니크 37%·어흥염 31%), 볼부비부비 6종, 분노의앞니 15종, 순풍 39종(패리퍼 14%), 트릭룸 46종(키키링 16%), 와이드가드 19종, 도우미 161종.

더블에서 승패를 가르는 것은 다음 **짝 단위 읽기**이고, 이것들이 설계의 1급 대상이어야 합니다.

| 읽기 | 내용 | 싱글에 없는 이유 |
|---|---|---|
| 방어(Protect) 읽기 | 상대 A 가 방어할 것 같으면 B 를 집중, 속이기 턴에 방어 | 두 대상이 있어야 "다른 쪽을 친다"가 성립 |
| 유도(따라와·분노가루) | 상대 단일 공격을 보조가 흡수, 짝이 셋업·강공 | 2v2 전용 |
| 집중 공격 vs 분산 | 둘이 한 대상을 쳐서 확정 처치 vs 범위기(0.75배)로 둘 다 | 결합 행동의 핵심 선택 |
| 속이기(Fake Out) 턴 | 1턴 풀죽음으로 상대 한 쪽 행동 삭제 + 짝의 순풍·트릭룸·셋업 | 첫 턴 템포 |
| 스피드 조절 | 순풍·트릭룸·얼다바람·볼부비부비가 4마리 전체 행동 순서를 바꿈 | 4마리 순서 |
| 위협 순환·교체 | 어흥염 위협 + 흩어지기 교체로 상대 물리 화력을 계속 깎음 | 교체가 공격의 일부 |
| 파트너 보호 | 범위기(지진·파도타기)에서 파트너 무효 특성(부유·저수)·와이드가드 | 아군 피해 |
| 메가 시점 | 한 번뿐인 메가를 어느 짝에 | 2마리 중 선택 |

### 4.2 짝(duo) 표현

- **짝 토큰** = 두 포켓몬 벡터(2.2.2) + 필드 토큰을 입력으로 하는 **짝 인코더**(2층 d=128 어텐션, [DUO] 출력). 선출·배틀이 공유합니다.
- 짝 인코더 입력에 **엔진이 계산한 짝 서술자**을 추가합니다(이름이 아니라 계산값이므로 새 포켓몬에 일반화):

| 짝 서술자 | 계산 | 차원 |
|---|---|---|
| 2×2 데미지 행렬 | 내 짝 각각 → 상대 짝 각각 최고 기술 기대 데미지%·처치확률 (단일/범위 둘 다, 범위기는 0.75배·파트너 피해 포함) | 2×2×4 = 16 |
| 4마리 행동 순서 | 순풍·트릭룸·마비·끈적끈적네트 각각의 가정 아래 내 두 마리가 상대 두 마리보다 빠른가 | 4×4 = 16 |
| 유도·보호 | 짝에 따라와/분노가루/와이드가드/방어/속이기/앞질러가기/도우미/볼부비부비/분노의앞니/얼다바람 보유 여부 + 우선도 | 12 |
| 범위기·파트너 안전 | 범위기 보유, 파트너가 그 타입 무효/반감인가(특성 포함: 부유·저수·피뢰침·텔레파시) | 6 |
| 스피드 조절 설치·수혜 | 순풍/트릭룸 설치자 + 짝의 실스피드가 그 아래서 상대 분포 상위 몇 % | 6 |
| 위협·흡수 | 위협 보유, 상대 짝 물리 비율, 클리어바디류 | 4 |
| 셋업+유도 짝 | 한쪽 랭크업 기술 × 다른 쪽 유도 보유 | 2 |

- **더블 배틀 상태 토큰**: 내 활성 2(자리 a/b 임베딩) + 내 벤치 2 + 상대 활성 2 + 상대 벤치 2(미공개면 믿음망의 "선출 예측"으로 부드럽게) + 전역 1 + 짝 토큰 2(내 짝·상대 짝) + 역사 8 = **21토큰**, 4층 d=192. 역사 토큰에 "방어 성공/실패, 유도 발동, 풀죽음, 집중 공격으로 처치" 이벤트 유형을 넣습니다 — 방어 2연속 불가·상대의 방어 버릇이 여기서 보입니다.

### 4.3 턴마다 동시행동 행렬게임 (2v2)

결합 행동 a = (a_1, a_2), a_s ∈ {기술 j 대상 t [메가], 교체 b, 패스}. 수가 100~400 이므로 후보를 **인수분해 + 매크로 템플릿**으로 뽑습니다.

1. **인수분해 정책 헤드**: 점수(a) = s(a_1) + s(a_2) + φ(h_{a_1}, h_{a_2}). 보조 손실로 자리별 주변분포 CE 를 함께 학습 → 결합 공간에서 상위 K=8 을 열거합니다.
2. **매크로 템플릿 강제 포함**(정책망이 약해도 핵심 읽기가 행렬에 들어가도록): 집중 공격(대상 A / 대상 B 각각 최고 기술), 분산 공격, 범위기, 방어+공격(어느 쪽이 방어하는지 2가지), 속이기+X, 유도+셋업/스피드 조절, 교체+공격(위협 순환), 메가+공격. 합법인 템플릿을 후보에 더해 **K_me ≤ 12**.
3. 상대 후보 K_opp ≤ 12 도 같은 방식(상대 시점 정책망 + 템플릿). 상대 **행동 예측 헤드**는 VGC 기보로 학습한 사람의 결합 행동 분포(방어율·교체율·집중률이 자연히 들어감).
4. 세계 W=4 × 12×12 = **576 복제/턴**(더블 1턴 적용 ~5 ms → ~3초 실전, 생성 모드는 W=3·K=8 → 192 복제 ~1초). 리프 = 가치망 배치.
5. 가중 평균 행렬 → 내시 (p*, q*) → q = (1−λ)q* + λ q_pred → RNR 최선응답. **방어/유도/집중/교체 확률**은 p* 에서 직접 읽혀 UI 에 "이 턴 방어 32%·집중 51%·교체 17%"로 표시합니다.
6. 기록: 후보 목록·p*·q*·행렬 M̄(12×12)·루트값. **행렬 자체를 저장**하는 이유는 아래 보조 기술 가치 학습 때문입니다.

### 4.4 보조 기술의 가치를 실제 결과로 배우기

보조 기술(따라와·도우미·볼부비부비·분노의앞니·순풍·방어)은 데미지가 0 이라 손변수로는 가치가 없습니다. 세 겹으로 배웁니다.

| 신호 | 라벨 | 손실 |
|---|---|---|
| 판 결과 | 가치망 z' = 0.5·승패 + 0.5·루트값 | BCE |
| **행동 이득(advantage)** | 각 후보 a 에 대해 A(a) = (M̄ q)_a − p*ᵀ M̄ q (상대 혼합 q 아래서 이 행동의 기대값 − 루트값). 보조 행동이 공격보다 높으면 양수 | 정책 헤드 보조 회귀 MSE, λ=0.2 |
| **선출 조밀 라벨** | 보조 포켓몬이 선봉 짝에 들어간 1턴 상태의 가치 vs 빠진 상태 | 선출망 MSE (4.5) |

이 세 신호는 모두 "실제 대전·탐색 결과"에서 나오므로, 따라와의 가치는 **그 턴에 짝이 무엇을 할 수 있게 됐는가**로 결정됩니다. 검증(합격 기준의 일부): 보조+에이스 벤치마크 팀(4.6)에서 탐색이 유도·속이기를 고르는 턴의 A(a) 가 양수인 비율, 그리고 해당 기술을 **금지한 절제(ablation) 대전**에서의 승률 하락폭(≥5%p, 400판)으로 측정합니다.

### 4.5 더블 선출 — 선봉 짝 + 후열 짝

- 행렬 90×90 (C(6,4)=15 조합 × C(4,2)=6 선봉 짝). 선출 i 임베딩 = **[짝 토큰(선봉 2)] ⊕ [짝 토큰(후열 2)] ⊕ 위치 임베딩**. M(i,j) = σ(g(e_i, e_j, 문맥) − g(e_j, e_i, 문맥)).
- **조밀 라벨**: (i,j) 마다 "선봉 4마리 필드·후열 4마리 벤치·HP 100%" 1턴 상태를 가치망으로 W=4 세계 평균 → 8,100칸/매치업, GPU ~2.5초. 더블은 1턴(속이기·순풍·트릭룸)이 판을 좌우하므로 **선봉 짝 매치업**이 라벨에 바로 반영됩니다.
- 희소 보정: 실제 (내 선출, 상대 선출, 승패) BCE; 상대 선출 예측 q_h 는 VGC 기보의 (양팀 6 → 선출 4·선봉 2)로 학습(리드율 사전확률과 비교).
- 결정은 2.5 와 같은 RNR. UI 에는 "선봉 짝별 기대값 상위 5 + 각 짝의 역할(유도·스피드 조절·속이기)" 을 표시합니다.
- 후보 추리기에 **1:1 상성표를 쓰지 않습니다**(가치망 라벨이 전체 90×90 을 ms 에 채우므로 추릴 필요가 없음).

### 4.6 VGC 기보·데이터 형태·벤치마크

**기보**: 형식 `gen9championsvgc2026regm*` (Bo3 포함; Bo3 의 2·3게임은 같은 판으로 취급하되 `bo3_game` 필드를 기록해 뒤에 "판 간 적응"에 쓸 수 있게 둡니다). 해석 개선: 대상이 불명확한 53% 를 줄이기 위해 `|-damage|`·`|-immune|`·`|-miss|` 줄의 대상 귀속과 `[spread]` 태그로 대상을 복원 → 목표 **하나로 정해진 비율 ≥70%**. 남는 모호함은 부드러운 라벨(일관된 결합 행동들에 균등).

**결정 기록 형식(더블)**

```
{ side, turn, kind: "turn"|"force"|"preview",
  view(스냅숏, 자리 a/b 포함), req(압축),
  options: ["move 1 2, move 3 1", ...],            # 전체 합법 결합 행동 (수백)
  cands: [idx...]  (K_me ≤ 12, 템플릿 포함),
  probs: p* over cands, oppCands: [...], oppMix: q,
  matrix: 12×12, rootValue, worldWeights,
  chosen: idx, macro: "focus_A|spread|protect_a+attack|fakeout|redirect|switch|..." }
```

텐서 캐시: 토큰 21×d 입력, 결합 행동 후보 ≤12 × (자리별 행동 2 × 행동 임베딩), 자리별 주변분포 2×(≤14), 행렬 12×12, 라벨 z'.

**손실(더블 배틀망)**: CE_joint(p*) + 0.5·Σ_s CE_marginal + BCE_value(z') + 0.2·MSE_advantage + 0.2·CE_oppJoint(q 또는 사람 행동) + 0.3·L_belief + 0.1·MSE_remaining.

**벤치마크 더블 팀 (각 아키타입 2변형, 쇼다운 validator 통과, `benchmarks/archetypes_doubles.json`)**

|---|---|---|
| 보조+에이스 (유도) | 파밀리쥐(따라와·분노의앞니·앞질러가기) + 한카리아스 / 불카모스(분노가루) + 셋업 에이스 | 유도 읽기·보조 가치 |
| 보조+에이스 (마비·템포) | 브리무음(볼부비부비·트릭룸·앞질러가기) + 느린 강공격수 | 스피드 뒤집기 |
| 속이기+위협 순환 | 어흥염/포푸니크 + 흩어지기 교체 | 첫 턴 템포·교체 가치 |

각 벤치마크는 탐색 v2(더블) 가 조종하며, 지표는 승률(Wilson CI, 200판), **보조 포켓몬 선출률·선봉률**, 턴당 방어/집중/유도 선택 비율, 보조 기술 절제 시 승률 하락폭입니다.

## 부록 A. 통계 공식

- Wilson 95% 구간: 중심 (p + z²/2n)/(1 + z²/n), 반폭 z·√(p(1−p)/n + z²/4n²)/(1 + z²/n), z=1.96.
- SPRT (p0=0.50, p1=0.55, α=β=0.05): 판마다 LLR += ln(p1/p0) (승) 또는 ln((1−p1)/(1−p0)) (패); LLR ≥ ln((1−β)/α)=2.94 채택, ≤ ln(β/(1−α))=−2.94 기각. 기대 판 수 ~400~900.
- 두 조건 승률 차 Δ 검출(검정력 80%): n_각 ≈ 2·(1.96+0.84)²·p(1−p)/Δ².
